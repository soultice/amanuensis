# Plan 06-01: Bug Fixes — CSP, Model Progress, WaveSurfer Reload, Pinia markRaw, Session Restore

## Objective

Fix five critical runtime bugs that prevent the app from being functionally usable end-to-end:
1. CSP blocks annotation images (file:// URLs from userData)
2. Model download progress never reaches renderer (stuck at 0%)
3. WaveSurfer doesn't reload when audio recording completes
4. Pinia reactivity crashes on native browser objects (MediaRecorder, MediaStream, WaveSurfer)
5. Session restore fails silently when words lack segmentId (export produces empty output)

## Must-Haves

1. Annotation images from `userData/sessions/assets/` display in `AnnotationPanel`
2. Model download shows real progress (not stuck at "checking")
3. Waveform renders after recording stops
4. App doesn't crash from Pinia proxying native objects
5. Export works after session restore (words mapped to segments)

## Wave 1 — Bug Fixes

### Task 1.1 — Fix CSP to allow `file://` for annotation images and audio

**Bug:** Annotation images and audio clips are stored in `app.getPath('userData')/sessions/assets/` and served as `file://` URLs. The current CSP `img-src 'self' data: blob:` blocks `file:` scheme, so images never display. Similarly `media-src 'self' blob:` blocks audio file playback.

<read_first>
- src/main/index.ts (Content-Security-Policy header in onHeadersReceived)
- src/renderer/index.html (CSP meta tag)
</read_first>

<action>
In `src/main/index.ts`, update the CSP string inside `onHeadersReceived`:

Change:
```
"default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self' http://localhost:*; img-src 'self' data: blob:; media-src 'self' blob:"
```

To:
```
"default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self' http://localhost:*; img-src 'self' data: blob: file:; media-src 'self' blob: file:"
```

In `src/renderer/index.html`, update the `<meta http-equiv="Content-Security-Policy">` content attribute to the same value:
```html
content="default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self' http://localhost:*; img-src 'self' data: blob: file:; media-src 'self' blob: file:"
```
</action>

- `src/main/index.ts` contains `media-src 'self' blob: file:`
- `src/renderer/index.html` contains `img-src 'self' data: blob: file:`

### Task 1.2 — Fix model download progress: poll sidecar and forward via IPC

**Bug:** `useModelStore.startDownload()` subscribes to `model:progress` IPC events, but no one ever sends them. The main process doesn't poll the sidecar during download, so `model_manager.progress` is never forwarded to the renderer. The onboarding screen shows "Downloading Whisper large-v3…" forever with 0% progress.

<read_first>
- src/main/index.ts (model:download handler and where to add polling)
- sidecar/app/services/model_manager.py (state and progress fields)
</read_first>

<action>
In `src/main/index.ts`, update the `model:download` IPC handler to poll the sidecar for progress and forward it to the renderer:

Replace:
```typescript
ipcMain.handle('model:download', async () => {
  const port = getSidecarPort()
  if (!port) throw new Error('Sidecar not ready — cannot start model download')
  const res = await fetch(`http://localhost:${port}/model/download`, { method: 'POST' })
  if (!res.ok) throw new Error(`Download request failed: ${res.status}`)
})
```

With:
```typescript
ipcMain.handle('model:download', async () => {
  const port = getSidecarPort()
  if (!port) throw new Error('Sidecar not ready — cannot start model download')

  // Start the download (returns immediately — sidecar runs it in a background thread)
  const res = await fetch(`http://localhost:${port}/model/download`, { method: 'POST' })
  if (!res.ok) throw new Error(`Download request failed: ${res.status}`)

  // Poll sidecar for download progress and forward to renderer via model:progress event
  const win = BrowserWindow.getAllWindows()[0]
  if (!win) return

  const pollInterval = setInterval(async () => {
    try {
      const statusRes = await fetch(`http://localhost:${port}/model/status`)
      if (!statusRes.ok) return
      const status: { state: string; progress: number } = await statusRes.json()

      // Forward progress to renderer
      if (!win.isDestroyed()) {
        win.webContents.send('model:progress', status.progress)
      }

      // Stop polling when download completes or errors
      if (status.state === 'present' || status.state === 'error') {
        clearInterval(pollInterval)
        if (status.state === 'present') {
          win.webContents.send('model:progress', 100)
        }
      }
    } catch {
      // Sidecar not reachable — continue polling
    }
  }, 500)
})
```

Also update the `model:get-status` handler to use the sidecar when available (it already does this but falls back to filesystem — keep as is for robustness).
</action>

<acceptance_criteria>
- `src/main/index.ts` contains `setInterval` inside the `model:download` handler
- File contains `win.webContents.send('model:progress', status.progress)`
- File contains `clearInterval(pollInterval)`
- File contains `status.state === 'present'`

### Task 1.3 — Fix model status race: re-poll after sidecar becomes ready

**Bug:** `App.vue` calls `modelStore.refresh()` at mount, but the sidecar starts asynchronously after. The model status is fetched before the sidecar is ready, falling back to filesystem check. This works for 'missing'/'present' states but doesn't correctly reflect 'downloading' or the real model status from the sidecar. After sidecar becomes ready, the model status is never re-checked.

<read_first>
- src/renderer/src/App.vue (current onMounted — adds sidecarStore.initialize then modelStore.refresh)
- src/renderer/src/stores/sidecar.ts (status field: 'starting' | 'ready' | 'error')
</read_first>

<action>
In `src/renderer/src/App.vue`, watch `sidecarStore.status` and re-poll model status when sidecar becomes ready:

```typescript
import { onMounted, watch } from 'vue'
import { useSidecarStore } from './stores/sidecar'
import { useModelStore } from './stores/model'

const sidecarStore = useSidecarStore()
const modelStore = useModelStore()

onMounted(async () => {
  await sidecarStore.initialize()
  await modelStore.refresh()
})

// Re-check model status once sidecar finishes starting
// This handles the race where refresh() runs before sidecar is ready
watch(
  () => sidecarStore.status,
  async (status) => {
    if (status === 'ready') {
      await modelStore.refresh()
    }
  }
)
```
</action>

<acceptance_criteria>
- `src/renderer/src/App.vue` contains `watch(`
- File contains `sidecarStore.status`
- File contains `status === 'ready'`
- File contains `await modelStore.refresh()`
- `npm run typecheck` exits 0
</acceptance_criteria>

### Task 1.6 — Fix session restore: add segmentId fallback when segments missing

**Bug:** Sessions saved before Phase 5 (or with sidecar returning words without `segmentId`) restore correctly for the transcript view but break the Markdown export: `words.filter(w => w.segmentId === segment.id)` returns empty arrays because `segmentId` is `undefined` on every word. Export produces just `# Transcript\n\n` with no text.

<read_first>
- src/renderer/src/stores/session.ts (restore() — where words are restored)
- src/renderer/src/stores/transcript.ts (Word interface, segments state)
</read_first>

<action>
In `src/renderer/src/stores/session.ts`, after restoring words, add a fallback to reconstruct `segmentId` and `segments` when they are missing:

```typescript
// Restore transcript
if (data.transcript) {
  // Ensure words have segmentId (may be missing from pre-Phase-5 sessions)
  const words = data.transcript.words.map((w, i) =>
    typeof w.segmentId === 'number' ? w : { ...w, segmentId: 0 }
  )
  transcriptStore.words = words

  // Restore segments — reconstruct a single segment if none were saved
  if (data.transcript.segments && data.transcript.segments.length > 0) {
    transcriptStore.segments = data.transcript.segments
  } else if (words.length > 0) {
    // Fallback: create one segment covering all words
    transcriptStore.segments = [{
      id: 0,
      start: words[0].start,
      end: words[words.length - 1].end,
      text: words.map(w => w.word).join('').trim(),
    }]
  }

  transcriptStore.language = data.transcript.language
  transcriptStore.duration = data.transcript.duration
  transcriptStore.transcriptState = 'complete'
}
```
</action>
