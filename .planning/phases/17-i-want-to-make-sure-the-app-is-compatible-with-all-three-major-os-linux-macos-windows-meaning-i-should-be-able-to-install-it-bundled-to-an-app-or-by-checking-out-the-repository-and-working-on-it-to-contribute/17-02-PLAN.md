# Plan 17-02: Fix Windows dev mode and electron-builder cross-platform config

## Objective

Two targeted fixes to make the project work correctly on Windows in dev mode and improve
the installer quality on all platforms:

1. **`src/main/sidecar.ts`**: The dev mode code currently adds `~/.local/bin` to PATH,
   which is the Poetry install location on Linux/macOS but **does not exist on Windows**.
   On Windows, Poetry installs to `%APPDATA%\pypoetry\venv\Scripts` (official installer)
   or `%APPDATA%\Python\Scripts`. Both paths must be added so `poetry.exe` is discoverable.

2. **`package.json` electron-builder config**: The Linux build is missing a `category`
   field (needed for the `.desktop` file the AppImage generates). The Windows build lacks
   NSIS options that improve the installer UX (allow directory selection, create shortcuts).

## Tasks

### Task 1: Fix Windows Poetry PATH detection in sidecar.ts

<read_first>
- src/main/sidecar.ts (full file — read the entire startSidecar() function before editing)
</read_first>

<action>
In `src/main/sidecar.ts`, locate the `startSidecar()` function. Find the dev-mode branch:

```typescript
  if (is.dev) {
    // Development: use Poetry
    const sidecarDir = path.join(process.cwd(), 'sidecar')
    command = process.platform === 'win32' ? 'poetry.exe' : 'poetry'
    args = ['run', 'python', '-m', 'app.main', '--port', String(port), '--user-data', userDataDir]
    cwd = sidecarDir
    // Ensure Poetry's install directory is in PATH (installed to ~/.local/bin by default)
    const poetryBinDir = path.join(require('os').homedir(), '.local', 'bin')
    process.env.PATH = `${poetryBinDir}${path.delimiter}${process.env.PATH}`
  }
```

Replace it with:

```typescript
  if (is.dev) {
    // Development: use Poetry
    const sidecarDir = path.join(process.cwd(), 'sidecar')
    command = process.platform === 'win32' ? 'poetry.exe' : 'poetry'
    args = ['run', 'python', '-m', 'app.main', '--port', String(port), '--user-data', userDataDir]
    cwd = sidecarDir

    // Prepend all known Poetry install locations to PATH so the platform-appropriate
    // poetry / poetry.exe binary can be found regardless of how Poetry was installed.
    const home = require('os').homedir()
    const poetryBinPaths: string[] =
      process.platform === 'win32'
        ? [
            // Official installer (https://install.python-poetry.org on Windows)
            path.join(process.env['APPDATA'] || path.join(home, 'AppData', 'Roaming'), 'pypoetry', 'venv', 'Scripts'),
            // Pipx-based install or pip install --user on Windows
            path.join(process.env['APPDATA'] || path.join(home, 'AppData', 'Roaming'), 'Python', 'Scripts'),
            path.join(process.env['LOCALAPPDATA'] || path.join(home, 'AppData', 'Local'), 'Programs', 'Python', 'Scripts'),
          ]
        : [
            // Official installer on macOS/Linux: ~/.local/bin
            path.join(home, '.local', 'bin'),
          ]
    process.env.PATH = `${poetryBinPaths.join(path.delimiter)}${path.delimiter}${process.env.PATH}`
  }
```

The `require('os')` call is already used in the file — no new import needed.
`path`, `path.delimiter`, and `process.env.PATH` are all available in Node.js scope.

Do not change anything else in the file. The production branch (`else`) and the rest of
`startSidecar()` must remain exactly as-is.
</action>
