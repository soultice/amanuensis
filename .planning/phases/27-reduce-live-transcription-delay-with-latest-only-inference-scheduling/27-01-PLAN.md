    In `sidecar/app/services/live_transcription.py`, implement the Phase 27 scheduler inside `LiveTranscriptionManager` itself per D-01, D-02, D-03, D-04, D-05, and D-06.

    Make these exact structural changes:
    - Add per-session scheduler state on `LiveSession` for one in-flight worker and one overwriteable latest snapshot: `pending_latest`, `worker_task`, `worker_wakeup`, `latest_seq_accepted`, `latest_seq_processed`, and `superseded_results_dropped`.
    - Keep `pcm_buffer` and `pcm_packet_ranges` as the canonical audio history. Do not drop audio bytes; only drop superseded inference work.
    - Refactor `ingest_pcm(...)` so the lock-protected section only validates `state in {'prepared', 'live'}`, exact `seq == next_expected_seq`, matching channel count, appends the PCM bytes, updates `last_seq` / `next_expected_seq`, stores a newest-snapshot record in `pending_latest`, updates `latest_seq_accepted`, and wakes exactly one per-session worker. Do not call `_transcribe_pcm_window(...)`, `_merge_words(...)`, or `push_output_event(...)` while the intake path is holding `session.lock`.
    - Add `_ensure_session_worker()` and `_run_session_worker()` helpers. `_run_session_worker()` must take the newest pending snapshot only, clear the slot, build the decode window with the existing `resolve_pcm_window_start_index(...)` and `build_pcm_window_blob(...)` helpers, run `_transcribe_pcm_window(...)` outside the lock, then reacquire the lock before merge/emit.
    - Preserve `FULL_RECONCILE_EVERY_N_CHUNKS = 8` and the existing bounded-tail helpers unchanged initially. The scheduler change is about choosing which snapshot to process next, not changing overlap or transport architecture.
    - Before merging a worker result, compare its snapshot generation/sequence against the current session scheduling state and drop stale completions. Increment `superseded_results_dropped` whenever a result is discarded because a newer snapshot was accepted while inference was running.
    - Keep the emitted event contract unchanged: `type: 'patch'`, `type: 'telemetry'`, `type: 'state'`, and `type: 'complete'` with the existing `replaceFromWordIndex`, `words`, `segments`, `language`, and `duration` field names preserved exactly per D-04.
    - Update `stop_session()` so if the session still has `pending_latest` work or an active worker, it drains one final newest-tail pass before sending the terminal `complete` event and HTTP stop payload. Do not reintroduce FIFO replay of every intermediate snapshot.
  </action>
