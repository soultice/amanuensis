# Plan 16-01: Make project installable on any machine

## Objective

Ensure anyone can clone this repo and run `npm install` successfully — even on machines with a corporate npm registry configured globally (e.g. Mercedes-Benz Artifactory). Achieve this via three small, targeted file changes:

1. Create a project-level `.npmrc` that pins the public npm registry
2. Add an `npm` version constraint to `package.json` engines
3. Update `README.md` to mention the npm version requirement

**Purpose:** The developer's `~/.npmrc` points to `registry=https://artifactory.euc1.cicd.oneweb.mercedes-benz.com/...`. Without a project-level override, any `npm install` on a non-MB machine will fail with 404s because that corporate registry is unreachable externally.

**Output:** `.npmrc`, updated `package.json`, updated `README.md`

## Tasks

### Task 1: Create project-level `.npmrc`

<read_first>
- ~/.npmrc (understand the global override being neutralised)
- package.json (confirm no existing npmrc reference or packageManager field)
</read_first>

<action>
Create the file `.npmrc` at the project root with this exact content (single line, no trailing blank lines):

```
registry=https://registry.npmjs.org/
```

This file is picked up by npm automatically when the working directory is inside the project. It overrides any user-level (`~/.npmrc`) or global registry setting. No additional configuration is needed — npm's registry resolution order is: project `.npmrc` → user `~/.npmrc` → global → built-in default.

Do NOT add any other settings (no `save-exact`, no `strict-ssl`, no auth tokens).
</action>

<acceptance_criteria>
- File `.npmrc` exists at project root
- `grep -c "registry=https://registry.npmjs.org/" .npmrc` returns `1`
- File contains exactly one line (no blank lines, no extra config)
- `wc -l < .npmrc` returns `0` or `1` (one line, possibly no trailing newline)
</acceptance_criteria>

### Task 2: Add npm engine constraint to `package.json`

<read_first>
- package.json (current engines field is `{ "node": ">=18.0.0" }`)
</read_first>

<action>
Edit `package.json` — update the `"engines"` field from:

```json
"engines": {
    "node": ">=18.0.0"
}
```

to:

```json
"engines": {
    "node": ">=18.0.0",
    "npm": ">=8.0.0"
}
```

Rationale for `>=8.0.0`:
- npm 8 shipped with Node 16 and introduced `--workspaces` and the lockfile v2 format used by this project
- This is a conservative floor: npm 8, 9, 10, and 11 all satisfy it
- Current dev environment uses npm 11.2.0 — well within range

Also add a `"volta"` field after `"engines"` to pin exact versions for Volta users:

```json
"volta": {
    "node": "22.14.0",
    "npm": "11.2.0"
}
```

The `volta` field is ignored by non-Volta environments, so it is safe to add unconditionally. Place it directly after the `"engines"` block.

Preserve all existing JSON structure and formatting (4-space indentation matching the file).
</action>

<acceptance_criteria>
- `node -e "const p=require('./package.json'); console.log(p.engines.npm)"` prints `>=8.0.0`
- `node -e "const p=require('./package.json'); console.log(p.engines.node)"` prints `>=18.0.0`
- `node -e "const p=require('./package.json'); console.log(p.volta.node)"` prints `22.14.0`
- `node -e "const p=require('./package.json'); console.log(p.volta.npm)"` prints `11.2.0`
- `node -e "require('./package.json')"` exits 0 (valid JSON)
- `grep -c '"npm": ">=8.0.0"' package.json` returns `1`
</acceptance_criteria>
